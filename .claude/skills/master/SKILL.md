# master

この会話を「入口」にする。頼まれたことは自分でやらず、いむたろとすり合わせて依頼を固め、Herdr のタブを開いて子の Claude に渡す。1 タスク = 1 タブ = 1 Claude。タブの操作は herdr-control スキル（`~/.claude/skills/herdr-control/SKILL.md`）の書き方に従う。状況の確認はこのスキルではしない。

子は入口の会話を見られない。渡した依頼文がすべてなので、曖昧なまま渡すと子が推測で走り、やり直しになる。だから開く前にここで固める。

## /master <やりたいこと>

1. **分ける。** 別々に進められるものだけを分ける。迷ったら 1 つのまま。一度に開くのは 3 タブまで。
2. **すり合わせる。** タスクごとに次の 4 点が、いむたろの言葉・この会話・今のフォルダから読めるか確かめる。
   - **終わりの形**: 何ができたら完了か（PR がマージ済み／報告だけ／ファイルができた、など）
   - **場所**: どのフォルダ・リポジトリで作業するか
   - **範囲**: どこまでやるか、触ってはいけないもの、後戻りできない操作（削除・公開・送信）を許すか
   - **前提**: 子が知らないと迷う事情（関連する Issue・URL・既に決めたこと）

   読めない点だけを質問する。読めたことは聞かず、仮置きした内容を確認に載せる。確かめるのはフォルダの存在など最小限で、調査はしない（調査は子の仕事）。質問は 1 回にまとめ、各問に「こうだと思う」という案を添える。答えは自由記述で受け、選択肢で閉じない。

   4 点とも読めるなら質問せず次へ進む。聞くことを増やすために聞かない。
3. **見せて固める。** 子に渡す依頼文を、タブ名・フォルダ・「モデル / effort」の 1 行付きで 1 画面に出し、いむたろの OK を待つ。直しがあれば直して再提示する。OK が出るまでタブは開かない。4 点が最初から読めていたときは、依頼文を示して 1 往復だけ確認する。

   「モデル / effort」の決め方:
   - 既定は「指定なし（settings.json の値）」。そう書いて見せる
   - 指定を案に出すのは、明らかに軽い仕事（Notion のページ作成・会議室の予約など）のときと、いむたろが「最高戦力」などと明示したときだけ。案は見せるだけで、OK で決まる。見せずに変えない
   - モデルは `fable` / `opus` / `sonnet` / `haiku`（その系列の最新）か、`claude-sonnet-5-5` のような正式名。effort は `low` / `medium` / `high` / `xhigh` / `max`。渡せる値は `claude --help` の `--model` / `--effort` が一次情報
   - Fable を使うときは、開く前に理由を一言添える

   タブ名は日本語の短い名前にする（例「データポータル棚卸し」）。英語の略名にしない（2026-11-28 本人の指示）。
4. **開く。** OK の後、タスクごとに 1 回:

   ```bash
   herdr-app do tab.new '{"name":"<短い名前>","folder":"<フォルダ>","argv":["claude"],"task":"<子への依頼>"}'
   ```

   モデルか effort を指定したときだけ、`argv` に足す。指定しないものは書かない。

   ```bash
   herdr-app do tab.new '{"name":"<短い名前>","folder":"<フォルダ>","argv":["claude","--model","sonnet","--effort","low"],"task":"<子への依頼>"}'
   ```

   起動時の `--model` / `--effort` はそのセッションだけに効き、settings.json は変えない。効いたかは子の画面のヘッダ（例 `Sonnet 5.5 with low effort`）で分かる（2026-11-27 に確認）。

   子への依頼は次の形で書く。いむたろの言葉は削らずに入れる。

   ```text
   <やること>
   <すり合わせで決まった前提・範囲・触らないもの。無ければこの行は書かない>
   終わりの形: <何ができたら完了か。PR / 報告 / 修正済みなど>
   このタブは /master から開いた 1 タスク専用。別件はしない。
   終わったら最後に「結果:」で始まる 1〜3 行（やったこと・出口の URL やファイル・残ったこと）を書いて止まる。
   ```

5. **報告して終わる。** 返事の JSON に `error` が無いことと `herdr-app ls` でタブができたことを確かめ、開いたタブ名を伝えて終わる。子の終わりは待たない（待つと入口が塞がる）。

## しないこと

- 自分で作業しない。調べものやコードの変更は子に渡す
- すり合わせの前にタブを開かない。急ぎと言われても、4 点が読めていなければ聞く
- モデルと effort を、見せた 1 行と違う値で開かない
- 子の承認待ちに代わりに答えない。いむたろがそのタブで答える
- 子のタブを閉じない。閉じる・畳むのは頼まれたときだけ（herdr-control の「閉じる」）
- 自分が開いたタブ以外には触らない
