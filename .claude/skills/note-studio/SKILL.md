# note-studio — note 制作室

## この工程の原則

1. **転がなければ書かない。** 事実と気づきを並べただけの記事（承止まり）は完成としない
2. **書き出しは三行以内で撃つ。** 外したら読まれない前提で設計する
3. **稿を分業する。** 1回で仕上げようとしない
4. **説明せず、場面で語る。** 感情は書かず、感情が生まれた場面を書く

土台は書籍『三行で撃つ』（近藤康太郎）。本文中の「第N発」はその出典番号。深掘りが要るときだけ `~/.claude/skills/books/三行で撃つ/`（別リポ管理・無い環境もある）を読む。**無くてもこのスキル内の規約だけで完結する。**

## 前提

- **Vault**: `/Users/imutaakihiro/repos/imutaakihiro/ObsidianImus/`
  - 入力: `Notes/` 配下のなぐりがき（読むだけ）
  - 出力: `Private/AI workspace/YYYY-MM-DD-{slug}.md`（1案件=1ノート）
  - 画像: `Private/AI workspace/images/`
- **`Vault/` 配下には1バイトも書き込まない**（いむたろ様の聖域）
- **一人称は「僕」**（固定）。書き詰まったときに一人称を変えて書き直すのは練習として可だが、公開版は「僕」に戻す（第10発・第13発）
- **公開の主導権はご主人様**: このスキルは note に投稿しない。md を仕上げて投稿手順を案内するところまで
- **捏造禁止**: 実体験の種だけを使う。入力に無い描写を補ったら本文に `【要確認】` を残し、確認を取ってから確定する
- 長い記事は骨子 `Write` → 節ごと `Edit`

## Step 1: 企画を立てる（第14発）

1. 問いを変換する。「何を書くべきか」ではなく **「僕に、なにが、書けるのか」**
2. **喜怒哀楽のどれを撃つか宣言する。** 狙いは「楽」＝他者を喜ばせること。自分が笑うために `（笑）` `w` `草` を書かない（あれは他者への攻撃・第7発）
3. **先に「なにを書かないか」を決める。** そこに余白が生まれる
4. 読者との距離は**半歩先**。一歩先は読者を置き去りにする
5. **判定: 自分が驚いたか。** 驚いていないなら読者も驚かない。企画に戻る

なぐりがきが無ければ Step 0 として案内する:

> `Notes/` に該当するなぐりがきが見つかりません。先に自分の言葉で書いてからもう一度呼んでください。（Vault はいむたろ様の聖域。AI は書き込めません）

## Step 2: 転を決める【ゲート】（第6発）

**ここを通らないと Step 3 に進まない。** 五パターンから選び、転を1行で言語化してご主人様に見せる。

| 型 | note での実行 |
|---|---|
| **①古今** | その習慣・言葉・道具の由来まで時間を遡る（WebSearch 可・裏取り必須。数字は一次ソースが取れたものだけ） |
| **②東西** | 他社・他業界・他国ではどうかを調べ、「絶対はない」と示すだけでいい |
| **③逆張り** | 世間の逆を張る。逆を言うだけでは浅い。**問題を設定し直して構造まで転がす** |
| **④順張り** | 世間の本音にいったん同意し、度を越して進める。アイロニーが要る（最難） |
| **⑤脱臼** | 話の筋をわざと変える。**ユーモアが無いとただの脱線**（軽量テンプレ・転が出ない日の逃げ道） |

- 転を書けるとは〈考えることができる〉ということ。ここが AI にも他人にも書けない部分なので、**ご主人様の頭から出させる**。AI が代わりに転を作らない
- 「言うまでもなく」で始まる主張は転にならない（反論の余地がない命題は弱い）
- 転が出ないなら**その日は書かない**。無理に進めると必ず承止まりになる

## Step 3: 起を撃つ（第1発）

- **最初の一文、長くても三行以内**で読者を撃つ
- 一行目は**捨て球であり伏線**。読み終えたときに意味が分かるよう仕込み、**必ず回収する**（撃ちっぱなしは「けれん味」で最悪）
- **禁じ手**: 時日・場所からの書き出し（「21時、会議室で。」）／一文目の体言止め／記事を動かさない数詞／凡庸出だし（「〜に行った」「〜について書きます」）
- 読者像は「読書エリート」ではない。**落ち着きがなく、考えたくもない人**
- **3案以上つくり、いちばんのけぞるものを選ぶ**

## Step 4: 承を書く（第6発・第7発）

- 5W1H を簡潔に。**ここに感想を入れない**
- **感情を説明しない。感情が生まれた場面を切り取る。**「嬉しかった」ではなく、そのときの動作・セリフ・音を書く
- 「肩をふるわせた」のような借り物の動作に逃げない。固有の動作を探す
- 視覚だけにしない（聴覚・嗅覚・触覚・味覚）
- **場面が出てこないなら素材が足りない。** ご主人様に聞く。想像で埋めない

## Step 5: 結を書く（第6発）

- 結は独立に考案しない。**転という鐘が響かせる音**にすぎない
- 結が書けないときは結をひねらず、**手前の転を疑う**

## Step 6: 稿を重ねる（第23発）

| 稿 | やること | やらないこと |
|---|---|---|
| 第一稿 | 全部を大急ぎで吐き出す | 良し悪し・語彙・構成・スタイルを考えない |
| 第二稿 | 意味の通じる日本語に**翻訳**する | 磨かない |
| 第三稿 | 音読して**流れだけ**見る。流れない箇所は大幅に作り直す | 常套句狩り |
| 第四・五稿 | **やすり**（禁止リストの一掃・ダブり排除・省略） | 構成の作り直し |

大幅変更（構成・転・書き出し）は `_第N稿.md` で新版保存。軽微な修正は同ファイルを Edit。

## Step 7: 点検

**[references/publish-checklist.md](references/publish-checklist.md) の測定を全部実行し、実出力を添えて報告する。** 目視で「守れています」と言わない。

規約の全文は **[references/style-guide.md](references/style-guide.md)**（禁止リスト・積極ルール・版面規約）。

## 画像（必要なとき）

**[references/visual-style.md](references/visual-style.md) を読んでから始める。** アイキャッチ1枚＋「頭の中の図解」。見本1枚 → 承認 → 量産 → 全数検品の順を守る。

**本・映画の感想記事なら [references/eyecatch-review.md](references/eyecatch-review.md) が正本。** 3分割（左＝文字／中央＝実物の書影・ポスター／右＝ドット絵の本人）の型。書影は**生成せず実物を合成する**（`scripts/compose_cover.py`）。

## 仕上げモード: FBループ（オプトイン）

「ブラッシュアップして」等の明示指示があったときだけ、**[references/review-loop.md](references/review-loop.md)** を読んで回す。エージェント4体×数ラウンドと重いので初稿には使わない。

原則は第19発「**聞いて、聞くな**」。指摘は全部聞くが、言われたとおりには直さず注文の上を行く。抽象的な指摘が来たら、マイルドにする方向ではなく**ワイルドにする方向**で直す。

## Step 8: 完了報告

- ファイルパス・タイトル案・**転の1行**・見出しリスト
- lint の実出力
- **`【要確認】` を付けた箇所の全一覧**（入力に無い描写・自信のない数字・固有名詞）
- 実名を出した箇所と、事前共有の提案
- 投稿手順の案内（note へ貼り付け・公開時刻は朝7時 or 夜21時・X告知文）

## 失敗モード（このスキルがやりがちな失敗）

- **承で止まる**（事実＋「学びました」で終わる）。転ゲートを飛ばした証拠
- **銃を撃って回収しない**（強い一行目を書いたのに伏線が消える＝けれん味）
- 場面を書かずに要約する（「感じました」の連発）
- **AI が転を代作する**（ご主人様の考えを奪う。最も避けるべき失敗）
- guru ポジションに滑る／嘲り・説教・一刀両断（第22発。批判は剣ではなく笑いで）
- 実体験にない描写を盛る（→ `【要確認】`）
- Zenn 向きの技術解説が混入する（→ zenn-studio の担当）
