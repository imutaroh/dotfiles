# 感想記事のアイキャッチ（3分割・実物の書影入り）

本・映画・作品の感想 note で使う型。2026-08-15 に確立し、公開済み3本で実証した。

> **前提**: キャラクター（ドット絵の本人像）を描くので、生成前に必ず `imutaro-visual` Skill の
> `references/character.md` を開き、参照画像 `assets/character-reference.png` を渡す。
> 文章だけで作ると別人になる。

## 完成形

画面を横に3等分し、3つの要素を**同じ強さ**で並べる。

```
┌─────────────┬─────────────┬─────────────┐
│ BOOK NOTE ──│             │             │
│ 『作品名』著者 │             │    ドット絵  │
│ 前置きの1行   │  実物の書影   │    の本人    │
│ 主題（大）    │  ／ポスター  │             │
│ ───────     │  （高さ72%） │  （高さ80%） │
│ 朱の副題2行   │             │             │
└─────────────┴─────────────┴─────────────┘
  0〜33%          33〜67%         67〜100%
```

背景はクリーム `#faf3ec` 一色。フラットで影・グラデーションなし。

| 要素 | 指定 |
|---|---|
| ラベル | `BOOK NOTE` / `MOVIE NOTE`。小さいグレーのサンセリフ大文字＋右へ伸びるリーダー罫線 |
| 作品名 | 小さめのゴシック体・グレー `#5b6572`。`『作品名』著者名` |
| 前置き | 明朝体・墨色 `#1a2330`。主題の前フリになる1行 |
| 主題 | 明朝体・墨色。**行の横幅が画面幅の28%**になる大きさ |
| 副題 | 朱色 `#c0392b` の明朝体で2行。主題に見合う大きさ |
| 装飾 | ティール `#0e7a7a` 1色のみ、**1枚につき1モチーフだけ**。無しでもよい |

## 憲法1 との関係（重要）

`imutaro-visual` の憲法1「1枚の画像の中で系統AとBを混ぜない」に対し、この型は
**明朝タイポ（A寄り）＋クリーム地とドット絵キャラ（B）＋実物写真**を1枚に同居させる。
**感想記事のアイキャッチに限った明示的な例外**として運用する。線画インフォグラフィック
（本文の「頭の中の図解」）には持ち込まない。

## 手順

### 1. 文言を記事本文から拾う

主題・前置き・副題は、**本文に実際に書かれた言葉**からしか作らない。
図のために感情や出来事を足さない（`visual-style.md` の捏造ガードと同じ）。

### 2. 素材（書影／ポスター）を先に確保する

**生成AIに書影を描かせてはいけない。** 参照画像として渡しても再描画されるので、
偽の装丁・誤った著者名になる。必ず実物のピクセルを貼る。

```bash
# ISBN-10 / ASIN から書影を取得（上限は高さ500px）
curl -s -o cover.jpg "https://images-na.ssl-images-amazon.com/images/P/<ASIN>.09.LZZZZZZZ.jpg"

# メタデータ（タイトル・著者の正確な表記）の裏取りは openBD
curl -s "https://api.openbd.jp/v1/get?isbn=<ISBN13>"
```

- openBD は**書影が登録されていないことが多い**（実測：主要2冊とも `cover` が空）。
  タイトル・著者の確認用と割り切る
- 映画ポスターは配給会社の宣伝素材。**個人利用の範囲を超えるなら使わない**。
  判断はご主人様に確認する

### 3. 土台を生成する（中央は完全な空白）

`codex exec` で生成。中央3分の1に**何も描かせない**のが肝。

```
【構図・最重要】画面を横に3等分する。左3分の1が文字、中央3分の1は完全な空白、右3分の1が人物。

【左3分の1・文字サイズの指定が最重要】文字はすべて画面幅の33パーセントの内側に収める。
そのうえで主題の行「◯◯」は、行の横幅がちょうど画面幅の28パーセントになる大きさで描く。小さすぎてはいけない。
（1. ラベル 2. 作品名 3. 前置き 4. 主題 5. 罫線 6. 朱の副題2行）

【中央3分の1】画面幅の33パーセントから67パーセントまでは、上端から下端まで完全な空白。
文字も線も装飾も人物も一切描かず、背景のクリーム色だけにする。
ここには後から別の画像を貼るので、絶対に何も描かない。

【右3分の1】画面幅の67パーセントより右に、ドット絵の人物を1人だけ、画面の高さの8割を占める大きさで堂々と描く。

【厳禁】主題の行を画面幅の28パーセントより小さく描くこと。文字が33パーセントの線を越えること。
中央3分の1に何かを描くこと。人物を小さく描くこと。本の表紙・書影・実在の装丁の絵。
文字は上記のみ
```

### 4. 実物を合成する

```bash
python3 ~/.claude/skills/note-studio/scripts/compose_cover.py \
  <土台.png> <書影.png> <出力.png>
```

土台を **1280×720 に正規化**してから、中央に高さ72%で貼る。
`MAX_UPSCALE = 1.10` で拡大を止めているので、ボケる合成は起きない。

## なぜ 1280×720 なのか（変えるときは必ず読む）

書影の最大が**高さ500px**しかない。1664×936 のような大きいキャンバスに
「中央いっぱい（高さ72%＝674px）」で置こうとすると 1.35倍の拡大になり、ボケる。
1280×720 なら 518px で収まり、**拡大なしで中央いっぱいになる**。

キャンバスを大きくしたくなったら、先に500pxより大きい書影を確保すること。

## 検品（全数、画像を開いて見る）

`visual-style.md` の6項目に加えて、この型では次を見る。

1. **文字が33%の線を越えていないか**（書影が主題の末尾を隠す事故が実際に起きた）
2. **主題が小さすぎないか**（他の記事と並べたとき1枚だけ弱く見える）
3. **キャラが小さくなっていないか**（中央を大きくすると自動的に脇役に落ちる）
4. **ヘッドホンが省略されていないか**（キャラの最重要の識別子）
5. **書影の拡大率**（スクリプトの出力に `scale=` が出る。1.10を超えることはないが、1.0超なら要確認）

## 振り直しの実績（同じ穴に落ちないために）

| 症状 | 原因 | 効いた対処 |
|---|---|---|
| キャラが極端に小さい | 中央を72%にすると書影が最大要素になり、他が自動的に縮む | 「画面の高さの8割を占める大きさで堂々と描く。小さく描かないこと」 |
| 文字が中央にはみ出し、書影が主題の末尾を隠した | 「帯幅いっぱい」という曖昧な指示 | 「33パーセントの線を1文字も越えるな」とパーセントで境界を明示 |
| 今度は文字が小さすぎた | 上の禁止だけ効いてサイズの下限がなかった | 「主題の行の横幅が画面幅の28パーセント」と**数値で下限を固定** |
| 矢印が人物と関係を結ばず孤立／人物に突き刺さって見えた | 方向を持つ矢印は「関係」を表せない | 位置なら同心円、合流なら先端のない線、上昇なら階段状の矢印 |

## この型が破綻する条件

- **装丁が写真的な作品では浮く。** 書影2冊（白地・フラットな装丁）は馴染んだが、
  映画ポスター（暗い写真）はクリーム地の中で明確に浮いた。浮きが許容できないなら
  中央を空にして作品名の文字だけにする
- **実物の色がパレットを侵食する。** 書影の黄色・青がそのまま画面に入るので、
  「ティール1点」の原則は書影のある画像では成立しない
- **note のタイムラインで縮小されると、書影の中の文字は読めなくなる。**
  だから作品名は必ず**文字でも**左に置く（書影だけに頼らない）
