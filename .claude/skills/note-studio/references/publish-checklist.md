# 公開前点検

**全項目をコマンドで実測し、実出力を添えて報告する。** 記憶や目視で「守れています」と言わない。

`<記事>` は `Private/AI workspace/YYYY-MM-DD-*.md`。

## 1. 文体 lint（機械測定）

```bash
python3 ~/.claude/skills/note-studio/scripts/lint.py "<記事>"
```

- **FAIL は原則すべて直す。** 残す場合は「なぜ残すか」を報告に書く（例: 固有のメタファーとして意図的に置いた擬音）
- WARN は判断材料。特に「冒頭の数詞」は、その数字が**記事を動かすデータか**を自分に問う（第1発）
- 終了コード 1 = FAIL あり

## 2. 機械測定できないもの（人が見る）

lint は文体しか見ない。**記事の価値を決める部分は全部ここにある。**

- [ ] **転が1行で言えるか。**言えなければ承止まり＝未完成（第6発）
- [ ] **書き出しの一行が回収されているか。**撃ちっぱなしは「けれん味」（第1発）
- [ ] 場面が最低1つあり、そこで感情を**説明していない**（第7発）
- [ ] 見出しで転を先に割っていない
- [ ] 持ち帰りが1つだけ
- [ ] guru ポジション・嘲り・説教になっていない（第22発）

## 3. 音読（第18発）

```bash
# 画面で読むと目が滑るので、必ず声に出す。印刷できるならする
open "<記事>"
```

- 小さく声に出して読み、つっかえる箇所・句読点の位置を直す
- 目から離して**絵のように眺める**。黒っぽい（＝漢字が多い）ならひらがなに開く

## 4. 事実と配慮

```bash
grep -n "【要確認】" "<記事>"     # 入力に無い描写。ヒットしたら全部ご主人様に確認する
grep -nE "[0-9０-９]+" "<記事>"   # 数字。一次ソースで裏の取れないものは本文から外す
```

- [ ] 登場人物の実名を出した箇所を列挙し、**事前共有を提案した**
- [ ] 会社・取引先が特定できる情報が残っていないか

## 5. 体裁

```bash
python3 -c "import sys,re;t=open(sys.argv[1],encoding='utf-8').read();print('本文字数:',len(re.sub(r'\s','',t)))" "<記事>"
grep -c "^!\[" "<記事>"          # 画像枚数（アイキャッチ1＋見出し2〜3個に1枚が目安）
grep -oE "#[^ 　#]+" "<記事>" | tail -10   # ハッシュタグ 5〜7個
ls -lh "$(dirname "<記事>")/images/" | tail -10   # 画像サイズ
```

- [ ] タイトル40字以内
- [ ] ハッシュタグ5〜7個
- [ ] アイキャッチが用意され、**上下がトリムされても意味が通る**（visual-style.md）
