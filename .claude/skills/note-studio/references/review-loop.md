# FBループ（仕上げモード）

公開級に磨くための多エージェント反復レビュー。**オプトイン**で、初稿には回さない。

## 発動条件

- 公開前の最終仕上げ、または既公開記事の改訂
- ご主人様が「ブラッシュアップして」「FB部隊で」等と明示したとき
- コスト目安: エージェント4体×3〜4ラウンド

## 大原則: 聞いて、聞くな（第19発）

**指摘はすべて聞く。ただし言われたとおりには直さず、注文の上を行く。**

- **抽象的な指摘が来たらチャンス**。マイルドにする方向ではなく、**ワイルドにする方向**で直す
- 「無難にする」「角を取る」「一般論を足す」方向の指摘は、main の判断で**却下してよい**。却下理由を残す
- レビューは記事を平均に寄せる圧を持つ。それに抗するのが main の仕事

## 部隊編成（model は必ず明示。Fable 禁止）

レンズは**本の発に対応させる**。主観の「面白い／面白くない」では判定させない。

| 名前 | model | レンズ | 見るもの |
|---|---|---|---|
| brushup | opus | — | **唯一の編集者**。反映担当。ラウンドをまたいで文脈保持 |
| fb-gun | opus | 第1発 | 書き出しは三行以内で撃てているか。一行目の銃は**回収されたか**。禁じ手（時日場所・一文目体言止め・冒頭数詞・凡庸出だし）に触れていないか |
| fb-turn | opus | 第6発 | **転はあるか**。承で止まっていないか。転が1行で言えるか。「言うまでもなく」型の弱い命題になっていないか。結が転から自然に出ているか |
| fb-scene | sonnet | 第7発・第18発 | 感情を**説明**していないか。場面があるか。借り物の動作・常套句・形容詞の重ねがないか |

ファイルを編集するのは brushup だけ。レビュアーは read-only。図の生成・検品は main（visual-style.md）。

## 開始前に固定すること（全員のプロンプトに入れる）

1. **声の保護リスト**: 記事から著者の声（口癖・自己開示・締めの一言・固有のメタファー）を具体的に列挙し、**「消す・薄める提案は禁止」**と明記する。これが無いと FB ループは記事を無難な文章に磨耗させる
2. **捏造禁止**: 体験談・数字・感情の**新規追加は提案も禁止**
3. **転の代作禁止**: レビュアーが転そのものを書いて渡さない。「転が無い／弱い」と指摘するところまで
4. **版面規約は note を優先**（改行・太字・見出し。style-guide.md の3節）。ここを「本に反する」と指摘させない
5. **git・投稿操作禁止**

## ループ手順

```
R1: brushup が型を適用（転の明示・書き出し3案・場面の掘り起こし・禁止リスト一掃）
    → main が lint を実行
    → 3レビュアー並列でFB
R2〜: main が必須指摘を統合して brushup へ差し戻し → 反映 → 3レビュアー再FB
全員PASS後: 任意指摘から採用分だけ最終ポリッシュ → 回帰チェック限定の確認ラウンド → 完了
```

### main（リード）の裁き方

- **必須指摘が複数レビュアーで衝突したら、main が統合文言を決めて指定する**（brushup に判断を丸投げしない）
- **任意指摘の採否は main が決める**。採用基準: 事実の正確性に関わる／安くて確実に効く。不採用は理由付きで brushup に伝える（「触るな」リスト）
- **声・タイトル・転に関わる指摘は反映せず、ご主人様への最終報告に回す**

## 収束ガード（外すと無限ループする）

1. **判定様式を固定**: 1行目に `判定: PASS / FAIL`。**必須指摘0件なら必ずPASS**
2. **FAIL にできる条件を限定する**。これ以外では落とさせない:
   - 転が無い／承で止まっている
   - 書き出しの銃が回収されていない
   - 感情を場面ではなく説明で書いている
   - 禁止リスト（style-guide.md 1節）に触れている
   - 捏造の疑い
   - 声の毀損
   → **「面白くない」「もっと深く」「読者に伝わりにくい気がする」では FAIL にできない**
3. **すべての指摘に引用を義務付ける**（該当箇所20〜60字＋問題＋具体的修正案）。抽象的助言は禁止
4. **最終ラウンドは回帰チェック限定**: 「この○件の編集による回帰がないかだけ確認。新規の指摘拡張はしない」と明示
5. 毎ラウンド「基準は前回と同じ厳しさを維持し、PASS を安売りしない」と添える

## レビュアープロンプト雛形（共通部）

```
あなたは【レンズ名】として note 記事をレビューします。対象: <ファイルパス>

## 前提（指摘対象外の仕様）
- 著者の声はこの記事の価値: 【保護リストを列挙】。消す・薄める提案は禁止
- 体験談・数字・感情の追加提案は禁止。転を代わりに書くことも禁止
- 改行・太字・見出しは note の媒体規約に従っている。ここは指摘しない
- 一人称は「僕」で固定

## 見る観点
【レンズ別。gun=書き出しと回収、turn=転の有無、scene=説明でなく場面か】

## 判定できる FAIL 条件（これ以外では FAIL にしない）
転が無い／銃が回収されていない／感情を説明で書いている／禁止リスト該当／捏造の疑い／声の毀損

## 出力形式
1行目: `判定: PASS` または `判定: FAIL`
- 必須指摘（0件なら判定PASS）: 「該当箇所の引用（20〜60字）/ 問題 / 具体的な修正案」
- 任意指摘（判定に影響しない）: 同形式で簡潔に
抽象的な助言は書かない。SendMessage で main 宛てに報告。
```

## 完了報告に含めるもの

- ラウンド表（各レンズの PASS/FAIL 推移）と主な改善点
- **転が最終稿でも1行で言えること**の確認
- 声が無傷であることの確認
- **却下した指摘とその理由**（マイルド方向の指摘を却下したなら明示）
- 未反映の指摘（タイトル等の本人判断事項）
- 投稿はしていないことと、公開手順の案内
