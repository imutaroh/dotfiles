# Excalidraw Diagram

Obsidian vault に、あとから手で描き替えられる Excalidraw 図を生成する。

**このスキルの肝は「座標を手で書かない」こと。** 絶対座標と矢印バインディングを手で埋めると、要素が
増えたときに必ず破綻する。グリッド（col / row）だけ指定し、残りは `scripts/render.js` に計算させる。

## ワークフロー

### 1. 用途を確認する

| 用途 | 出力先 |
|---|---|
| 本人の理解・記録用 | **vault（このスキル）**。検索に乗り、`[[リンク]]` が張れ、手で描き替えられる |
| チーム・レビュアーに見せる | **Artifact**。このスキルは使わない（vault は共有できない） |

迷ったら聞く。両方要るなら vault に出してから Artifact を別途作る。

### 1.5 出力の既定（2026-08-18 合意）

- **指示がなければ図は1枚**。複数枚に分割するのは、利用者から明示的に依頼があったときだけ
- **解説用の .md は作らない**。説明・関数シグネチャ・注意点・未決事項は、すべて図中のノードと
  注記テキストに書き込む。「図＋別メモ」の2点セットは不採用（2026-08-18）
- 1枚に詳しく載せる基本形は**スイムレーン**：層（ディレクトリ）ごとに色付きヘッダの列を立て、
  実行順を ①②③… の番号付きステップで列をまたいで下に流す。破線 = 既存部品・外部
  （呼ぶだけ・つくらない）。ノードには ファイルパス・関数名・変数の受け渡し まで書く
- 補足知識（書く順番・写経元との差分・テスト方針など）は最下段に注記ノードとして置く

### 2. spec を書く

作業用ディレクトリに `spec.json` を書く。**座標は書かない。** col / row だけ。

```json
{
  "nodes": [
    { "id": "sch", "col": 1, "row": 0, "bg": "#a5d8ff", "label": "Cloud Scheduler\nqoo10-etl-dispatch" },
    { "id": "job", "col": 1, "row": 1, "bg": "#ffec99", "label": "Cloud Run Job" },
    { "id": "raw", "col": 1, "row": 2, "bg": "#ffec99", "label": "BigQuery Raw" }
  ],
  "edges": [
    { "from": "sch", "to": "job", "label": "テナント分だけ起動" },
    { "from": "job", "to": "raw" }
  ],
  "texts": [
    { "id": "title", "col": 0, "row": -0.85, "size": 28, "label": "取り込み経路" }
  ]
}
```

| キー | 対象 | 意味 |
|---|---|---|
| `id` | node / text | 一意。`edges` から参照する |
| `col` / `row` | 全て | グリッド位置。**小数可**（`1.5` で半コマずらせる） |
| `label` | 全て | `\n` で改行。1行は全角14文字/半角28文字が目安（既定幅 250px） |
| `bg` | node | 塗り。省略で透明 |
| `w` | node | 幅の上書き。省略で 250 |
| `dashed` | node / edge | 破線にする |
| `from` / `to` | edge | node の `id`。**辺のどこから出るかは位置関係から自動決定** |
| `label` | edge | 矢印の中央に乗るラベル |
| `bidir` | edge | 両端に矢印 |
| `size` / `color` | text | 単独テキスト用。タイトル 28 / 凡例・注記 15〜16 |

`layout` で `cellW` `gapX` `rowH` `gapY` `fontSize` を上書きできる。既定で足りることがほとんど。

配色は Excalidraw 標準パレットから選ぶと浮かない。青 `#a5d8ff` / 緑 `#b2f2bb` / 黄 `#ffec99` /
橙 `#ffd8a8` / 赤 `#ffc9c9` / 灰 `#e9ecef`（担当外・外部サービス）。

### 3. 生成する

> ⚠️ **既存ファイルの再生成前に、利用者にそのファイルのタブを Obsidian で閉じてもらう。**
> 開いたままディスク上のファイルを書き換えると、Excalidraw プラグインが古いメモリ状態とマージ
> 保存し、Text Elements セクションの重複→テキスト混入・要素消失を起こす（2026-08-17 実測）。
> 再生成後に疑わしいときは、セクション内の `^ref` に重複がないかを検査する。

```bash
node ~/.claude/skills/excalidraw-diagram/scripts/render.js spec.json \
  "/Users/imutaakihiro/repos/imutaakihiro/ObsidianImus/Private/Memos/<日本語のファイル名>.excalidraw.md"
```

- **出力先は vault の `Private/Memos/`**（Excalidraw プラグインの既定フォルダもここに設定済み）
- **ファイル名は内容がわかる日本語**。`Private/Memos` の既存ファイルが全て日本語名なので揃える
- 拡張子は `.excalidraw.md`。`.md` だけだと Excalidraw ビューで開かない
- 往復検証（id 重複・binding 解決・index 単調増加）が自動で走る。**NG なら exit 1 で止まる**

### 4. 検査結果を読む

`render.js` が構造検証（binding・id・index）とレイアウト検査（重なり・はみ出し）を自動で走らせる。
**出力を読み飛ばさない。**

```
構造検証 OK: 往復・id 重複なし・binding 全解決・index 単調増加
レイアウト検査: 要確認 2 件
  - ノード "api2" と ノード "raw2" が重なっている
  - ノード "c" はテキストが収まらず幅を 250 → 576 に広げた（...）
```

「要確認」が出たら spec を直して 3 に戻る。`col` / `row` は小数で半コマずらせる。長いラベルは
`\n` で折る。ジェネレータ経由なので作り直しは安い。

**スクリーンショットは撮らない。** Obsidian を前面に持ってくる必要があり、利用者の作業を中断させる。
明示的に「スクショで確認して」と頼まれたときだけ `scripts/preview.sh` を使う。

**レイアウト検査で拾えないのはフォントのフォールバックだけ**（日本語が豆腐になる類）。これは幾何計算
では判定できないので、利用者からの手動報告に頼る。ズレの報告を受けたら spec を直して 3 に戻る。

### 5. 報告する

図のパスと、目視で確認した内容を伝える。Obsidian 側で自由に動かして直せることも添える。

## 破綻する条件

**グリッドに載らない図には使えない。** 自由配置の概念図、注釈が飛び交うポンチ絵、軸上の重なりを
示す図などは col / row で表現できない。そういう図は**ジェネレータを無理に拡張せず**、
骨組みだけ生成して「あとは Obsidian で手で動かしてください」と渡すほうが速い。

要素が増えても既定は1枚（1.5 節）。交差は「列 = 層、行 = 時系列」のスイムレーン配置で避ける
（斜め矢印の通り道になるセルを空けておく）。レーンに整理してもなお交差が避けられないときだけ、
利用者に分割を提案して合意を取ってから分ける。
