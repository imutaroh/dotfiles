## 手順（全モード共通）

1. **正本を読む（スキップ不可）**：`$VAULT/Notes/CLAUDE.md` を Read。このスキルの記述と食い違ったら**正本に従い、食い違いを完了報告で1行伝える**（スキル側を直す起点）
2. **日付取得**：`date +%Y-%m-%d`（推測で書かない）
3. **同名検索**：`ls $VAULT/Notes/ | grep -i {候補名}`。同名があったら上書きせず「追記か別名か」を1問確認
4. **関連ノートを実物確認**：リンク先候補を Glob/Grep で探し、**実在を確認できたノートだけ** `[[リンク]]` する
5. **本文を書く**（下の「書式の要点」）。長くなるなら骨子 Write → 節ごと Edit
6. **検算する（下の「機械検算」・スキップ不可）**。不合格なら直してから次へ
7. **結線する**：該当トピックページ（例 `[[API]]` `[[Go]]`、無ければ `[[Tech]]`）にリンク1行追記（幽霊ノート予防）。昇格モードでは元 Draft を `status: done` にし、Draft への既存リンクを Notes 側へ張り替える
8. **完了報告**：パス・字数・貼った結線を報告。最後に必ず一言「**自分の言葉で一度見直すと定着します**（`source: claude-draft` は見直したら外してOK）」。Publish への反映（公開）はご主人様が Obsidian 側で行う

## 書式の要点（正本は Notes/CLAUDE.md。ここは控え）

**命名（2026-08-18 改訂）**
- **用語そのままの短い名詞形が第一候補**：`JWT` `curl` `Bearer`。説明語尾（〜とは/〜の使い方/〜という書式/〜の違い）を足さない
- **一般名詞1語は禁止**（`認証` `API` `テスト`）：ハブ名を潰す＋リンクで中身が予想できない。固有名詞はOK
- 1語で言えないときだけ長いタイトル（例 `BigQueryのウィンドウ関数`）。30字以内・日付・実名・記号なし

**frontmatter（Notes 用）** — tags は付けない（2026-08-18 廃止）。成熟度も付けない（新規は無印＝育成中）

```yaml
---
type: tech
created: {date コマンドの値}
permalink: {英小文字ケバブケース}   # 必須
image: "https://imu-ogp.vercel.app/api/og?slug={permalinkと同じ値}"  # 必須
source: claude-draft               # AI 下書きの透明性マーカー。ご主人様が見直したら外す
---
```

memos Draft のときは ai-work 型（`type: ai-work` / `status: review` / `topic:` / `promote: tech`）＋本文冒頭に昇格用 frontmatter 案を `%%` コメントで置く。

**本文**
- タイトル見出しを書かない・冒頭要約を置かない・見出しは `##` から
- 軸は `## What` → `## How`（＋必要なら `## 落とし穴`）→ 末尾 `## 関連`（トピック1本以上＋横リンク1本以上）
- **結論先出し**：各 `##` 見出しの直下1文目に結論。見出しは命題形を優先（`## What — 中身は読める` のように後置きで補ってよい）
- 5行ルール（本文テキスト5行以上連続させない）。視覚化の使い分け：数え上げ→箇条書き／比較→表／還流・分岐→mermaid（1個まで。文章で追える直線プロセスは図にしない）
- 太字は1段落1箇所・キーワードのみ。本文は意味的マークアップだけ（HTML タグ・インラインスタイル・装飾記号を書かない。見た目は publish.css の仕事）
- **落とし穴は「読者がいま踏む穴」だけ1〜2個**。全部盛りにしない（2026-08-18 の失敗：網羅した結果2,000字になった）
- 対話で使った言い換え・念押しを書き写さない。ノートは読み返す前提なので一度言えば足りる

**callout（本文の流れから外れるものだけを囲む。本流の文を囲むとノイズ）**

| 種類 | 役割 | 位置 |
|---|---|---|
| `[!info]` | 例え話・背景・前提（読み飛ばしても本筋が通じるもの） | 補足対象の直後 |
| `[!warning]` | 失敗談・落とし穴 | 読者が落ちる前（対象の直前〜直後） |
| `[!success]` | 結論・持ち帰り | `## 関連` の直前に固定 |

各1個まで・合計2個目安（3個入る時点で本文の設計を疑う）。**連続で置かない**（地の文の橋渡しなしに箱を並べると取ってつけた感が出る）。この3種以外は使わない。

## 機械検算（書いた後に必ず実行・意志で守らず数字で止める）

```bash
# ① 字数（frontmatter を除いた本文）。tech は 400〜1200 字。超えたら削ってから提出
awk 'f>=2{print} /^---$/{f++}' {ファイル} | tr -d '[:space:]' | wc -m

# ② 必須フィールド。1行も出なければ不合格
grep -c "^permalink: .\+" {ファイル}; grep -c "^image: .\+" {ファイル}

# ③ 結線。## 関連 が無ければ不合格
grep -c "^## 関連" {ファイル}
```

- ① が 1200 超 → **内容を選び直す**（言い換え削除→落とし穴絞り込み→節の統合の順）。1500 超は分割
- ① が 400 未満 → 薄すぎないか一度見直す（無理に膨らませない）
- 検算結果（字数）は完了報告に必ず載せる
