# Kindle for Mac の実機挙動と復旧手順（2026-08-20 実測）

## 症状 → 原因 → 復旧の索引

| 症状 | 原因 | 復旧 |
|---|---|---|
| `screencapture -l` が「could not create image from window」 | ウィンドウが描画されていない（別 Space がアクティブ / 最小化 / 画面ロック中） | ユーザーに Kindle を可視状態にしてもらう（下記「可視の条件」） |
| 同上（取り込み中に散発） | ページめくりアニメーション中の一時的なキャプチャ不能（3連発まで観測） | アプリ側が自動リトライする。散発なら無視 |
| キー送信が完全に無反応（キャプチャがバイト一致のまま） | (a) Kindle 起動直後で一度もクリックされていない (b) 取り込み中にマウスカーソルがウィンドウに乗った | `click_rearm.js` でページ本文をクリック（下記） |
| 取り込みが本の途中で「完了」してしまう | キー無反応 → 同一ページ2連続 → 最終ページと誤判定して自動停止 | 完了検証（フッター読取）で検出し、再アーム → 続きを再取り込み |
| 実キー（System Events）でも無反応 | 上と同じ。キー送信方式の問題ではなくアプリ内部のフォーカス喪失 | 同上。**タイトルバークリックでは直らない。ページ本文をクリックすること** |

## 可視の条件（キャプチャできる条件）

- ウィンドウが**どこかのディスプレイのアクティブな Space** に載っていること（前面である必要はない。他ウィンドウの背面でも撮れる）
- 最小化していない・画面ロックしていない
- 本を開いてもウィンドウ ID は変わらない。**アプリを再起動すると pid / windowID とも変わる**（`windowlist.js` で取り直す）

## click_rearm.js の使い方

```bash
# ウィンドウ位置を取得
osascript -l JavaScript scripts/windowlist.js
# → {"found":true,"pid":P,"windowID":W,"x":X,"y":Y,"width":WD,"height":HT}

# ページ本文の中央をクリック（左右端はページ送りゾーンなので避ける）
osascript -l JavaScript scripts/click_rearm.js $((X + WD/2)) $((Y + HT/2))
```

- 戻り値 `ABORT: frontmost is ...` = 前面化に失敗（ユーザーが操作中）。数秒待って再試行
- 数秒だけユーザーのフォーカスを奪う。実行前にひとこと断る
- クリックでツールバーが表示状態になることがあるが、キャプチャ品質には致命傷でない
  （ページ上部にツールバー・右下に「Nに戻る」チップが写り込む程度）

## 再アーム後の検証（必須）

クリックしただけで直ったと思い込まない。キーを1発送って**実際にページが変わる**ことを確認する:

```bash
screencapture -l <windowID> -o -x before.png
osascript -l JavaScript scripts/sendkey.js <pid> 123
sleep 1.2 && screencapture -l <windowID> -o -x after.png
md5 -q before.png after.png   # 異なれば復活。この1ページ進んだ状態から再開してよい
```

注意: 検証で1ページ進むが、続きの取り込みは「現在表示中のページ」から始まるので取りこぼしにはならない（進めた分を戻さないこと。戻すと1ページ重複する）。

## その他の実測値

- osascript の起動コストは1回 0.11〜0.12 秒。取り込み速度は約 1.2 秒/ページ（適応待機込み）
- 1画面 = 印刷版の約2ページ分（ウィンドウが横長の場合）
- ダークモード表示でも視覚読解・pHash とも問題ない
- 完了検証でフッターを読むには、ツールバーが出ている状態のキャプチャが必要なことがある
  （通常表示ではフッターの「Nページ中のMページ目・X%」が出ない。click_rearm 直後のキャプチャには出る）
