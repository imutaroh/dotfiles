# YouTube リサーチ

YouTube Data API v3 で動画データを取得 → 伸び率を計算 → 整形してチャットで報告する。
成果物はチャット報告で完結する。Notion 等外部への格納は、ユーザーが明示的に指示した場合のみ行う。

## 前提

- `jq` が必要（インストール済みのはず）
- API キーは `scripts/yt.sh` が「env 変数 `YOUTUBE_API_KEY` → macOS Keychain の `youtube-api-key`」の順で自動解決する
- キー未設定エラーが出たら、ユーザー自身に次を実行してもらう（AIは Keychain に書き込めない）:
  `! security add-generic-password -a "$USER" -s youtube-api-key -w 'APIキー' -U`

## ワークフロー

### 1. クエリ設計（テーマから「よしなに」）

「このテーマで調べて」を受けたら、キーワードをユーザーに聞き返さず、**テーマから角度の違う
検索クエリを2〜3本、AIが設計して回す**（例: テーマ「恋愛」→「恋愛 心理」「恋愛相談」など）。
どんなクエリを設計したかは報告に明記する。

- 1語クエリはジャンルが偏る（検証済み:「恋愛」→恋愛漫画系が支配的。「恋愛 心理」でハウツー系に変わる）。
  原則2語に絞り込む
- 期間・shorts・件数の指定がなければデフォルトで進める: 全期間 / duration=any / 25件
- クエリ1本=100ユニット。1回のリサーチは3本まで。それ以上回したい時はユーザーに確認する
- 目的がどうしても読めない時だけ AskUserQuestion（デフォルトは聞かずに走る）

### 2. データ取得（scripts/yt.sh）

```bash
S=~/.claude/skills/youtube-research/scripts/yt.sh
"$S" search "恋愛 心理" 25 7 medium   # クエリ, 件数, 直近N日(省略可), duration(省略可) → 100ユニット
"$S" stats <videoId,...50件まで>       # 再生数・高評価・投稿日時 → 1ユニット
"$S" channels <channelId,...50件まで>  # 登録者数 → 1ユニット
"$S" uploads <channelId> 10            # チャンネル新着監視 → 2ユニット
"$S" resolve-channel <ハンドル名>       # @ハンドル→channelId → 1ユニット
```

- 出力はすべて TSV。各コマンドの列は `yt.sh` を引数なし実行でヘルプ表示
- **チャンネル監視に search を使わない**（100ユニット）。`uploads`（2ユニット）で同じ結果が取れる
- stats / channels はIDをカンマ連結して**必ず50件バッチ**で呼ぶ（1件ずつ呼ばない）
- パラメータ詳細・クォータ計算・拡張アイデアは [references/api_reference.md](references/api_reference.md)

### 3. 伸び率の計算

取得した数値から2つの指標を計算する（Claude が計算して表に載せる）:

| 指標 | 式 | 意味 |
|---|---|---|
| 伸び率 | 再生数 ÷ 登録者数 | チャンネル規模に対してバズっているか。2.0x 以上が「伸びている」目安 |
| 勢い | 再生数 ÷ 投稿からの経過日数 | 1日あたり再生。古い動画の伸び率過大評価を補正する |

- **伸び率だけで判断しない**。1年前の動画は伸び率が高く出る。「直近N日に絞る」か「勢い」を併記して補正する
- 登録者数百人以下のチャンネルで伸び率が異常値（10x超）になったら「バズの種」として別枠で報告する
- 経過日数は `date` コマンドで現在日時を取得して計算する（記憶で計算しない）

### 4. 整形してチャットで報告

1動画あたりこの項目を揃え、**伸び率降順の表＋所感**で報告する:

タイトル（URL `https://www.youtube.com/watch?v=<videoId>` へのリンク）/ チャンネル名 / 登録者数 /
再生数 / 投稿日 / 伸び率 / 勢い（再生/日）/ どのクエリでヒットしたか

- 数値が取れなかった項目は空欄にし、**推測で埋めない**
- 複数クエリの結果は重複動画を除いてマージする
- 表の後に所感（傾向・バズの種・意外な発見）を数行つける

### 5. 報告時の注意

- 消費クォータの概算を必ず添える（例:「今回 103/10,000 ユニット」）
- 検索結果が意図とズレていたらキーワード変更を提案する
