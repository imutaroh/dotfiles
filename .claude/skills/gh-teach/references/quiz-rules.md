# 確認ドリルの作問規約

正本は Notion「🧪 Ingestion のスキルチェック」の作問ルール（https://app.notion.com/p/3bf022d569d381639cc3d69ae3768a81）。この規約はそれを練習用ドリルに写したもの。食い違ったら Notion を読み直して合わせる。

## 構成

| 区分 | 問数 | 中身 |
| --- | --- | --- |
| 基本 | 6 | 用語と仕組みを、自分の言葉で言えるか。1問1論点 |
| 応用 | 4 | 実務の場面（ファイル・テーブル・コード・ログ）を置き、「最初に取る行動」や「原因」を選ばせる。基本の論点を2つ以上組み合わせる |
| 追試 | 4 | 本試と同じ論点を別の文脈から。本試で詰まった論点を優先する |

- レベルは Lv.1（初心者）＝「読んで意図を説明できる」。操作手順の暗記は問わない
- 本人が工程2〜3で間違えた・詰まった論点は `focus: true` を付け、必ず1問以上入れる

## 1問の書き方

- 4択。問題文は場面か問いを1〜2文で。「選んだ理由も合わせて答えてください」の姿勢は、ドリル側の理由欄が担う
- 選択肢は **4つとも同じ長さ・同じ文の形**（主張＋理由または帰結）にする。正解だけを丁寧に書かない
- 誤答は「よくある誤解」から作る。本人が実際に言った間違いが最良の誤答になる
- 正答位置は A〜D に均等配分する
- 正答は一次資料で裏取りする。コード・コマンドの挙動は手元で実行して確かめる。確かめられなかったことは解説に「（〇〇の記述による・未検証）」と書く

## 回答例（解説）の4点

| フィールド | 書くこと |
| --- | --- |
| `point` | 理由の論点。正答を選んだ理由として何が言えれば十分か |
| `wrong` | 他の選択肢が不正解の理由。1選択肢1文 |
| `more` | 追加で聞くなら。1問先に進む問いと、その答え |
| （正答） | `a` に 0〜3 |

## ドリル HTML

雛形は `assets/drill.html`。置き換えるのは次の5か所。

- `{{TITLE}}`（2か所。例「C01-101 確認ドリル」）・`{{EYEBROW}}`（例「GH スキルチェック ・ C01 データ表現」）・`{{INTRO}}`（使い方を1〜2文）・`{{FOCUS_LABEL}}`（例「前回つまずいた所」）
- `/*QUESTIONS*/` を問題の配列要素に置き換える

```js
{ level: "基本", tag: "3層", focus: true,
  q: "問題文（HTML 可）",
  o: ["選択肢A", "選択肢B", "選択肢C", "選択肢D"],
  a: 1,
  point: "理由の論点",
  wrong: "A: …。C: …。D: …",
  more: "「…は？」→ …" },
```

- 不可視文字・置換文字（U+FEFF / U+200B / U+FFFD）は生で書かない。`&#xFFFD;` のように文字参照で書くか、`U+200B` と文字で書く。生で書くと公開ツールに拒否される
- 公開前に `node scripts/check_drill.mjs <file>` を通す。NG は必ず直す。WARN（選択肢の長さのばらつき・正答が一番長い・正答位置の偏り）も直してから公開する
