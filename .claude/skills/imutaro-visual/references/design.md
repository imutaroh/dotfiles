## 1. コンセプト（一文で言えること）

> **データエンジニアのフィールドノート** — 計器・ログ・端末の語彙で、学びの記録を淡々と美しく見せる。
> その白い紙の上に、**ドット絵の本人**が立つ。

- 語り口は静か。装飾は情報を運ぶものだけ（罫線＝区切り、mono＝メタ情報、点＝状態）
- 面で塗らない。**色は線と文字に置く**
- 賑やかさで勝たない。**余白と精度**で勝つ

## 2. 2つの系統と使い分け（最重要）

いむたろらしさは**単一パレットではない**。用途の違う2系統を、混ぜずに運用する。

| | **系統A：フィールドノート線画** | **系統B：ドット絵キャラクター** |
|---|---|---|
| 何 | 情報を運ぶ図・UI・タイポ | 人格を運ぶ顔 |
| 背景 | `#fafbfc`（ほぼ白） | `#fbf2e8`（クリーム）※透過切り抜きが基本 |
| 描き方 | 細い均一線・フラット・影なし | ドット絵（`image-rendering: pixelated`） |
| 人物 | **禁止** | 主役 |
| 使う場所 | Zenn/noteの図解、章扉、資料、サイトのUI全般 | プロフィールアイコン、LPヒーロー、名刺カード、SNS |

**憲法**:
1. **1枚の画像の中でAとBを混ぜない**。線画図解の中にキャラを置かない
2. **同じ画面には同居してよい**（サイトLP＝白い紙＝A の上に、B のバストが立つ）
3. **主役は1つ**。金属質の演出画像は2026-08-14に全廃済み、復活させない（キャラと主役を取り合うため）

## 3. タイポグラフィ

| 役割 | フォント | 使い所 |
|---|---|---|
| 見出し（Display） | 欧文 **Playfair Display 700** ／ 和文 **Zen Old Mincho 700** の混植 | h1〜h6、セクション番号、章扉のタイトル |
| 本文 | **IBM Plex Sans JP**（400/500/700） | 読ませる文 |
| メタ情報 | **IBM Plex Mono** | 日付・タグ・ID・ラベル・パンくず・図注 |

原則:
- **mono＝機械が読む情報**（日付・hash・ステータス・URL）、**sans＝人間に向けた文**。1つのテキスト内で混ぜない
- **serif＝見出しと構図を作るディスプレイ文字**。本文や小さなメタには使わない
- 見出しは 700 未満にしない（700 しか読み込んでいない）
- 画像生成では和文明朝の再現が不安定なので、**図解の日本語は「モダンなゴシック体」で指定する**（サイトの明朝を画像で真似しない）

## 4. モチーフ（このブランドの署名）

図でも資料でもスライドでも、迷ったらこの語彙から選ぶ。**ここにない装飾を発明しない。**

1. **ミニダイヤル ◉** — 輪＋中心点。見出しの eyebrow に付ける計器の目印
2. **エディトリアルの括弧** — `( 01 / about )` の形式で小見出しを書く
3. **リーダー罫線** — eyebrow から右端まで走る細い水平線。紙面に基準構造を与える
4. **ヘアライン行リスト** — 1px の罫線で区切った行。hover で淡い面が敷かれる
5. **code-tab カード** — 上部に mono のタブを持つ枠線カード（`profile.json` の型）
6. **mono ピル** — 角丸999pxの細枠＋mono小文字。タグ・ステータス用
7. **点とリング** — タイムラインのノード

セクション見出しの型:

```
◉ ( 01 / about ) ──────────────
01. About
```

### 不変条件（新しいカットを作るときも必ず守る）

- 黒髪ショート、切れ長の目、穏やかな微笑み。**若い日本人男性・新卒エンジニア**

## 6. すぐ使えるプロンプト（コピペ用）

生成の正規ルートは **Codex CLI の image_generation**（ChatGPT認証・APIキー不要）。
`cd <保存先リポ> &&` を必ず付ける（cwd リセットで保存先がズレた実績あり）。

```bash
cd <保存先ディレクトリ> && codex exec --sandbox workspace-write "image_generation ツールで16:9の画像を1枚生成し、images/<名前>.png に保存してください。

【スタイル・厳守】（↓のブロックをそのまま貼る）

【内容】（レイアウトを具体的に。ラベル文言は「」で正確に指定）
文字は上記のみ" 2>&1 | tail -2
```

`run_in_background: true` で並列（同時5本まで／1枚2〜3分）。

### A-1. 線画インフォグラフィック（本文図・資料図）

```
【スタイル・厳守】上質でミニマルな線画インフォグラフィック。背景 #fafbfc。線と文字は墨紺 #1a2330 の細い均一な線画、補助の小さな文字は #5b6572。強調・矢印のアクセントにだけシアン #00add8。薄い面パネルは #f0f3f6、罫線 #e3e8ed。影・グラデーション禁止、角丸ごく小さく、余白広め、フラットで精密。日本語はモダンなゴシック体。キャラクター・マスコット・手描き感禁止。
```

内容指定の末尾に必ず「**文字は上記のみ**」を付ける（余計なラベルの湧きを防ぐ）。

### A-2. タイポグラフィ・カード（アイキャッチ／章扉）

```
【レイアウト】上質でミニマルなタイポグラフィ主体のカード（16:9）。イラスト・人物禁止。
- 上部に小さく「（章番号やシリーズ名）」（数字だけシアン）
- 中央に大きくタイトル「◯◯」、その下にサブタイトル「◯◯」
- 下部に横並びのキーワードタグ3〜5個（シアンの細枠の小カード）:「◯◯」「◯◯」「◯◯」
- タグの下に細いシアンの水平ライン
- 文字は上記のみ
```

- note は横長の上下をトリムするので、**文字は中央に寄せ上下端に置かない**
- サブタイトルにカギ括弧があるときは「⚠️先頭と末尾に余計なカギ括弧を足さない」を明記（二重カギ括弧の事故あり）

## 7. 生成したら必ず検品（全数、画像を開いて見る）

1. **日本語の描画崩れ**（誤字・欠け・存在しない字形）— 生成画像の最頻の不良
2. **スタイル逸脱**（指定外の色・影・グラデーション・手描き感・湧いたマスコット）
3. **本文との整合**（図が本文の比喩と矛盾していないか。例:「引き出しはない」と書いた机に引き出しが描かれた）
4. **本文に無い出来事・感情・数字を描いていないか**（体験談で最重要。図のために事実を足さない）
5. 指定していないラベルの湧き・余計なカギ括弧
6. アイキャッチは**上下がトリムされても意味が通るか**

不合格は同じプロンプトに「⚠️〜は絶対に描かない」を足して上書き再生成する。

**プロセスの原則**: スタイルに関わる生成は、**まず1枚だけ作って見せ、承認を得てから量産**する。

## 8. アンチパターン

- ❌ アクセント色での面塗り（ボタン以外）
- ❌ 線画図解の中にキャラクター・マスコットを描く
- ❌ 1枚の画像に系統Aと系統Bを混ぜる
- ❌ 影付きカードの多用（カードは1画面に1つの主役だけ）
- ❌ mono と body の混用（役割で使い分ける）
- ❌ トークンを介さない生色指定（Webでは `var(--color-accent)` を使う）
- ❌ 無限ループするアニメ／スクロール連動演出（すべて撤去済み・復活させない）
- ❌ 生成画像としての金属・クローム（2026-08-14 に全廃）
- ❌ 読むページ（記事・ブログ）への演出の持ち込み。持ち込むのは**トーンだけ**
