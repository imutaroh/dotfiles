# キャラクター再現プロンプト（検証済み・2026-08-15）

`imutaro-visual` Skill の reference。キャラクターを**もう一度作る／新しいカットを足す**ためのプロンプト一式。
原本の生成プロンプトは記録が残っていなかったため、**画像から逆算 → 実際に生成 → 原本と照合**して確定させたもの（v2 で収束）。

> ⚠️ **参照画像なしでは同一性は保証できない。** 必ず `-i` で参照画像を添付する。
> - 既定（どの環境でも使える・Skill 同梱）: `~/.claude/skills/imutaro-visual/assets/character-reference.png`（三面図 640px）／`assets/profile-reference.png`（バスト 512px）
> - 原寸が要るとき（Vault がある環境のみ）: `~/repos/imutaakihiro/ObsidianImus/Studio/Brand/icon/`
> プロンプトが担うのは「画風・装備・配色」、参照画像が担うのが「顔の同一性」。

## 使い方（3ステップ）

1. 下の**共通ブロック**をそのまま使う
2. 末尾に、作りたいシートの**【構図】**を1つ足す（§3 から選ぶ）
3. 生成後、§4 の照合をかける

## 1. 実行コマンド

```bash
cd <保存先ディレクトリ> && cat prompt.txt | codex exec --sandbox workspace-write --skip-git-repo-check \
  -i ~/.claude/skills/imutaro-visual/assets/character-reference.png
```

**ハマりどころ3つ**（2026-08-15 に全部踏んだ）:

| 症状 | 原因 | 対処 |
|---|---|---|
| `No prompt provided via stdin` | `-i` は複数値を取るオプションなので、後ろに置いた**プロンプト引数まで画像として食われる** | プロンプトは引数で渡さず **stdin にパイプ**する（上記の形） |
| `Not inside a trusted directory` | git リポ外（scratchpad 等）で実行した | `--skip-git-repo-check` を付ける |
| 保存先がズレる | codex が cwd をリセットする | 必ず `cd <ディレクトリ> &&` を先頭に付け、保存先は**相対パス**で指定する |

1枚あたり2〜3分。並列は5本程度まで。

## 2. 共通ブロック（コピペ・確定版）

```
添付した参照画像と同一人物・同一画風のキャラクターイラストを、image_generation ツールで1枚生成し、指定パスに保存してください。

【画風・厳守】
16bitレトロゲーム（SNES期JRPG）風のドット絵イラスト。ピクセルの階段が視認できる粗さで、アンチエイリアスは最小限。輪郭は濃い線で明確に閉じる。陰影はセル調の2段（ベース色＋暗色）のみで、グラデーション・光沢・写実的な質感は使わない。全体はアニメ調の整った顔立ち。

【人物・厳守】
20代前半の日本人男性。黒髪のショートヘアで、毛先に束感があり前髪は眉にかかる程度。太めのまっすぐな眉、切れ長の黒い瞳、口角を少し上げた穏やかな微笑み。肌は明るいベージュ。

【服装・厳守】
濃紺（ほぼ黒に近い紺）のシングルスーツ、白いドレスシャツ、無地のロイヤルブルーのネクタイ。

【装備・厳守】
黒いオーバーイヤーヘッドホンを首にかけている（省略禁止・最重要の識別子）。

【カラーパレット・厳守】
背景 #fbf2e8（クリーム無地・模様なし）／スーツ #101223／ネクタイ #183f8a／肌 #fec889／髪と輪郭線 #0d1020／シャツ 白

【頭身・厳守】頭を大きくしない。7頭身のリアルな比率で、デフォルメ・ちびキャラ化は禁止。

【最暗色・厳守】純黒 #000000 は使わない。輪郭線・髪・スーツの最も暗い部分は #0d1020 とする。

【禁止】
写真的表現、3DCG、金属光沢、床に落ちる影、背景の模様やグラデーション、ロゴ、文字、透かし、他の人物。
```

**この2行が効いた**（v1 → v2 の差分。落とすと再発する）:
- 「頭身」— v1 は顔のアップに寄りすぎ、頭が大きくなった
- 「最暗色」— v1 は輪郭に純黒 `#000000` が出て、原本の `#0d1020` より硬い印象になった

### 場面カット（テック以外）を作るときの差し替えルール

不変条件は「スーツ＋白いキーボード／ノートPC」を前提にしているが、日常の場面（食事・スポーツ・趣味）を描くときは以下だけ差し替えてよい。**それ以外は動かさない。**

| 動かしてよい | 動かしてはいけない |
|---|---|
| **小道具**（場面に必要な1つだけ。丼・カメラ・ボール等） | **首にかけた黒いヘッドホン**（識別子。どの場面でも残す） |
| **服装**（スーツが不自然な場面のみ。ただし**濃紺基調は維持**。例: サッカー → 濃紺のスポーツウェア） | 顔・髪型・体型・配色パレット・画風・頭身 |
| 表情・視線（場面に合わせる） | 背景（クリーム無地のまま。店内・芝生・観客を描かない） |

**捏造ガード**: 小道具に文字・ロゴ・紙幣の肖像を描かせない（【禁止】に明記済み。破ると商標・偽造の面倒が出る）。

#### 顔が隠れる構図は崩れる（2026-08-15 実測）

場面カット4枚（ラーメン / 札束 / サッカー / カメラ）を生成したところ、**カメラを構えて顔の半分が隠れるカットだけが不合格**になった。症状は2つ同時:

1. **画風が別物に崩れる** — 参照画像より色数が激減し、粗いドットで顔が潰れる（ファイルサイズが 1.5MB → 19KB に落ちたのが客観的な兆候）
2. **ヘッドホンが消える** — 顔まわりが小道具で埋まると、識別子が落ちる

**顔の一部が隠れる／小道具が主役になる構図では、共通ブロックに次の2つを足す**（足したら1発で通った）:

```
【参照画像との一致・最優先】画風・色数・線の細かさ・顔の描き込み量は、添付した参照画像と同じ水準にする。参照画像より色数を減らさない。参照画像より粗いドットにしない。顔が潰れるほど簡略化しない。
【装備・厳守】黒いオーバーイヤーヘッドホンを首にかけている。⚠️ヘッドホンは絶対に省略しない。小道具で隠さず、首元にはっきり見えるように描く。
```

**生成後の簡易判定**: 出力が数十KBしかなければ、色数が落ちて崩れている疑いが濃い。開く前にサイズを見る。

## 4. 照合（生成したら必ず）

### 4-1. 目視

Read で画像を開き、`icon/` の原本と並べて次を見る。

1. **ヘッドホンが首にあるか**（最頻の欠落）
2. 髪型・眉・目つきが同一人物に見えるか
3. デフォルメ化していないか（頭が大きくなっていないか）
4. 背景に模様・影・グラデーションが湧いていないか
5. 文字・ロゴ・透かしが入っていないか

### 4-2. 配色の実測（目視より確実）

```bash
python3 -c "
from PIL import Image
from collections import Counter
import colorsys
im = Image.open('<生成画像>').convert('RGB').resize((300,300))
c = Counter(im.get_flattened_data()); f=lambda t:'#%02x%02x%02x'%t
print('背景', f(c.most_common(1)[0][0]))
print('最暗', [f(k) for k,v in c.most_common(40) if sum(k)<120][:3])
blue=Counter(); skin=Counter()
for col,n in c.items():
    r,g,b=[v/255 for v in col]; h,s,v=colorsys.rgb_to_hsv(r,g,b)
    if s>0.5 and 0.5<h<0.72 and v>0.25: blue[col]+=n
    elif s>0.2 and h<0.12 and v>0.6: skin[col]+=n
print('タイ', f(blue.most_common(1)[0][0]), '／肌', f(skin.most_common(1)[0][0]))
"
```

**合格ライン**（2026-08-15 の v2 実測値）:

| 項目 | 原本 | v2 生成 | 判定 |
|---|---|---|---|
| 背景 | `#fbf4e8` | `#f9f1e7` | 合格（誤差2〜3） |
| ネクタイ | `#183f8a` | `#144196` | 合格（やや鮮やか。許容） |
| 肌 | `#fec889` | `#fec88d` | 合格 |
| 最暗色 | `#0d1020` | `#0b1024` | 合格（v1 は `#000000` で不合格だった） |

純黒 `#000000` が最暗色に出たら**不合格**。【最暗色・厳守】の行が効いていないので、再生成する。

## 5. 限界と破綻条件

- **完全一致は原理的に不可能**。原本がどのモデルで生成されたかの記録が無く、同じ文面でもモデルが変われば絵柄は寄らない。このプロンプトが保証するのは「同じ人物・同じ装備・同じ配色に見えること」まで
- **参照画像を外すと別人になる**。`-i` は必須
- **意図的に原本と変えた点が1つある**: 原本のノートPCには林檎風のロゴが描かれているが、このプロンプトは【禁止】でロゴを排除している（商標回避）。原本に完全に合わせたい場合だけ、この禁止を外す
- **破綻条件**: codex の `image_generation` が使えなくなる／ChatGPT 認証が切れると、この手順ごと動かなくなる。そのときはプロンプト本文（§2）だけを他の画像生成サービスに持ち込めば、画風の指定は流用できる
