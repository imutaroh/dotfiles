# imutaro-visual — ビジュアル・アイデンティティの正本

**画像を1枚でも生成する前に、まずここで系統を決める。** 決めてから該当の reference を開く。

## 1. 最初の分岐（30秒で決める）

| 作るもの | 系統 | 開く reference |
|---|---|---|
| 記事の本文図・概念図・資料の図・アイキャッチ・章扉 | **A：線画インフォグラフィック** | `references/design.md` §2・§3・§4・§6 |
| プロフィールアイコン・本人が登場するカット・SNSの顔・名刺 | **B：ドット絵キャラクター** | `references/character.md`（プロンプト全文と実行コマンド） |

**憲法（両方に共通・破らない）**

1. **1枚の画像の中でAとBを混ぜない。** 線画図解の中にキャラクターを描かない
2. 同じ画面には同居してよい（白い紙＝A の上に、B のバストが立つ）
3. 主役は1つ。生成画像としての金属・クロームは 2026-08-14 に全廃、復活させない

## 2. 系統A の要点（詳細は references/design.md）

- 背景 `#fafbfc` ／ 線・文字 `#1a2330` ／ 補助 `#5b6572` ／ **アクセントはシアン `#00add8` を1画面に1点だけ**／ 罫線 `#e3e8ed` ／ 淡い面 `#f0f3f6`
- 影・グラデーション禁止、余白広め、フラットで精密。日本語はモダンなゴシック体
- **人物・マスコット・手描き感は禁止**
- 大量生成の前に、サイト側のトークンと乖離していないか確認する:
  ```bash
  grep -E '\-\-color-[a-z-]+:' ~/repos/imutaakihiro/imutaro/app/globals.css | head -20
  ```

## 3. 系統B の要点（詳細は references/character.md）

- **参照画像なしでは別人になる。** 必ず `-i` で下記を渡す:
  - 全身・三面図が要るとき → `assets/character-reference.png`
  - バストアップ1枚のとき → `assets/profile-reference.png`
  - 原寸が必要なとき → `~/repos/imutaakihiro/ObsidianImus/Studio/Brand/icon/`（Vault がある環境のみ）
- 不変条件: 黒髪ショート／濃紺スーツ＋ロイヤルブルーのタイ／**首にかけた黒いヘッドホン（省略禁止）**／小道具は白いキーボードとシルバーのノートPCだけ
- 効く2行（落とすと崩れる）: 「頭を大きくしない・デフォルメ禁止」「純黒 `#000000` を使わない・最暗は `#0d1020`」

## 4. 生成コマンド（codex / 画像生成の正規ルート）

```bash
# 系統A（参照画像なし）
cd <保存先> && codex exec --sandbox workspace-write "image_generation ツールで16:9の図解画像を1枚生成し、images/<名前>.png に保存してください。
【スタイル・厳守】（references/design.md §6 の共通ブロックを貼る）
【内容】（レイアウトを具体的に。ラベル文言は「」で指定）
文字は上記のみ"

# 系統B（参照画像あり。プロンプトは必ず stdin にパイプする）
cd <保存先> && cat prompt.txt | codex exec --sandbox workspace-write --skip-git-repo-check \
  -i ~/.claude/skills/imutaro-visual/assets/character-reference.png
```

**ハマりどころ**: `-i` は複数値オプションなので後ろの引数を食う（→ stdin にパイプ）／git リポ外は `--skip-git-repo-check`／codex は cwd をリセットするので `cd <dir> &&` と相対パス保存が必須。1枚2〜3分、並列は5本まで。

## 5. 生成したら必ず検品（全数、Read で開く）

1. **日本語の描画崩れ**（最頻の不良）
2. スタイル逸脱（指定外の色・影・グラデ・手描き感・湧いたマスコット）
3. 本文との整合（図が本文の比喩と矛盾していないか）
4. **本文に無い出来事・感情・数字を描いていないか**（体験談で最重要）
5. 指定していないラベルの湧き・余計なカギ括弧
6. 系統B は配色を数値で照合する（`references/character.md` §4-2 のスクリプトと合格ライン）

不合格は同じプロンプトに「⚠️〜は絶対に描かない」を足して上書き再生成する。

**プロセスの原則**: スタイルに関わる生成は、まず1枚だけ作って見せ、**承認を得てから量産**する。
