# morning（朝のブリーフィング）

## 役割

これは **Skill を呼び出す Skill（オーケストレータ）**。個々の処理は既存の基盤・スキルに委譲し、morning 自身がやるのは「集約して1枚のブリーフィングにまとめて渡す」ことだけ。**その日の一手・計画を決めるのはご主人様であり、AI 上では決めない**（2026-08-02 決定。「今日の一手」の AskUserQuestion は廃止。ちゃんと計画を立てること自体には価値があるが、それは AI との対話の外でやる）。

- AIログの生成・日報書き込み → `daily-ai-log` スキル（Vault 書き込み特例はあちらが持つ）
- 使用量の集計 → `ai-usage-dashboard`（launchd が毎朝 7:30 に自動更新済み）
- タスクの正 → リポ直下の `Todo.md`（closed list・上限10。2026-08-03 転換。GitHub Issue は「複雑度2以上の案件の倉庫」に格下げされ、毎朝は見ない。設計は `Private/AI workspace/2026-08-03-august-task-system.md`）

morning が Vault に書いてよいのは次の4箇所**だけ**（`/morning` は常設許可スキル。2026-07-21 の都度許可制決定時に確認不要枠として明文化済み）:

1. **昨日**のノートの `## AIログ` — daily-ai-log 委譲分（ルールもあちら）
2. **今日**のノートの `## 朝のブリーフィング` セクション — ステップ6で追記
3. **今日**のノートの `### タイムカレンダー` — カレンダーから生成（2026-07-30 ご主人様指示で追加）
4. **今日**のノートの `### Action` — ブリーフィングから起こした今日のタスク（同上）

`### Memo` は**ご主人様の手書き領域**。骨組み（見出し＋書き方の一行）だけ置き、中身は絶対に書かない。他のセクション・他のノートにも触れない。

> ⚠️ 3と4は**新規作成時と、その枠がまだ空のときだけ**書く。ご主人様が自分で書き足した行が既にあれば、**その行は消さず、下に追記するだけ**にする。

## コスト方針（2026-07-24 決定）

朝のブリーフィングは毎日走る定型処理なので **Fable を使わない**。

#### 偉人FB（メンターFBが無い日のみ）

昨日の日報の内容に対して、偉人が1人、その人らしい視点で短くFBする。

2. **吉田松陰が当たったら `yoshida-shoin-fb` スキルに委譲**する（専用スキルが正）。それ以外はその場で生成
3. 生成ルール:
   - **5〜8行まで**。朝の読み物なので長文にしない
   - 昨日の日報の**具体的な記述を最低1つ引用**して語る（一般論だけの説教は禁止）

4. ブリーフィングでは「FB: なし」の代わりに「**偉人FB（本日: ◯◯）**」として載せる。ステップ6の日報追記にも含める

### 2. Claude Code 使用状況（レポートを起動してリンクを渡す）

**まず最新化と配信を必ず実行する**（2026-07-29 ご主人様指示。「毎朝どれくらい使ったかを見たい」ため、数値を出すだけでなくレポート自体を開ける状態にする）。


- `run.sh` は Haiku 要約も走るので**セッションが多い日は20〜80分かかる**。ただし launchd が毎朝 7:30 に済ませているので、`/morning` からの実行は増分だけで**通常1〜2分**。この前提が崩れるので **launchd は消さない**
- **鮮度判定はせず毎回叩く**（launchd がスリープで飛んだ日・7:30 以降のセッションを確実に拾うため）
- `run.sh` の終了コードで分岐する（2026-07-30 追加のロック機構）:
  - **0** = 集計完了（自分で実行、または先行の完了を待って完了）→ そのまま読む
  - **3** = launchd の実行が10分待っても終わらなかった → `data.js` は**昨日のデータが不完全な可能性**がある。「集計中のため暫定値」と明記して読む
  - **それ以外** = `collect.mjs` の失敗。既存 `data.js` を読み「（前回更新: 日時）」と付記
- どの分岐でも `generatedAt` を確認し、**今日でなければ必ず「（前回更新: 日時）」を添える**（先行プロセスが強制終了された場合、終了コード0でもデータが古いことがある）
- `serve.sh` が `started` / `already-running` のどちらを返しても成功。**終了コード2（ポート 8789 が別プロセス使用中）のときだけ** `file:///Users/imutaakihiro/repos/imutaakihiro/ai-usage-dashboard/index.html` にフォールバックし、その旨を一言添える

#### 週制限ゲージ（公式の枠%を取る・毎週使い切るための逆算）

Max 20x は定額なので、**目標は「週間制限に毎週到達する」こと**。そのために claude.ai の使用量ページから**公式の枠%**を読む（2026-07-24 実証済み。ドル換算からの逆算は公式枠と線形対応せず破綻するため**やらない**）。

手順（claude-in-chrome ツールで実行）:

1. `navigate` で `https://claude.ai/settings/usage` を開く（`/new#settings/usage` にリダイレクトされ、設定モーダルが出る）
2. `javascript_tool` で以下を実行してモーダルのテキストを取る:
   ```js
   const dlg = document.querySelector('[role="dialog"]'); (dlg ? dlg.innerText : document.body.innerText).slice(0, 3000)
   ```
3. テキストから拾う: **現在セッション%とリセットまで時間**／**週間・すべてのモデル%とリセットまで時間**／**週間・Fable%**／使用クレジット残高

出す形（逆算がキモ）:

```
週間制限: すべてのモデル XX%（残り YY%・リセットまで H時間M分）／ Fable ZZ%
→ 使い切るには 時速◯%ペースが必要（昨日までのペース: 時速◯%）
```

- **残り% ÷ 残り時間 = 必要ペース（%/h）**を必ず計算して出す。これが「今日どれだけ踏むか」の根拠
- リセットが当日中に来る週は「今日が最終日。残り◯%を◯時間で」と明示する
- Fable% が すべてのモデル% より先行しているときは「Fable は温存、踏むのは Opus/Sonnet」と添える
- フォールバック: Chrome が使えない・ログインが切れているときは、公式%は「取得失敗」と正直に書き、data.js の日次コスト（直近7日平均との比較）だけ載せる。**%を推定で捏造しない**
- 破綻条件: claude.ai の設定モーダルの DOM 構造・文言が変わったら手順2の抽出が壊れる。壊れたら `read_page` で実物を見て直す
- 冒頭の `./run.sh` が失敗（終了コード0・3以外）した場合は、既存の `data.js` をそのまま読み「（前回更新: `generatedAt` の日時）」と付記する

### 2.5. 今日のタイムカレンダー（2026-07-30 新設）

Google Calendar MCP で**今日**の予定を取り、**1時間ごとのグリッド**に落とす。「今日どこが空いているか」を一目で出すのが目的。

```
mcp__claude_ai_Google_Calendar__list_events
  startTime: <今日>T00:00:00+09:00
  endTime:   <今日>T23:59:59+09:00
  orderBy:   startTime
  timeZone:  Asia/Tokyo
```

出す形:

```markdown
| 時刻 | 予定 |
|---|---|
| 09:00 | ✅ ○○MTG 09:15–09:45（相手／場所） |
| 10:00 | ← いまここ・空き |
| 12:00 | 🍽 ランチ（–13:00・相手） |
...
- 終日: ○○（空き扱い）
- まとまった空き: **10:00–12:00（2h）／13:00–19:00（6h）**
```

ルール:
- **範囲は最初の予定の時刻から最後の予定の終了まで**。予定が無い日は 09:00–18:00 を既定にする
- **開始が半端な予定（09:15 等）は、その時間の行に実時刻を併記**して置く。行を15分刻みに割らない
- **現在時刻より前の枠には ✅、いま入っている枠には「← いまここ」**を付ける（`date` で取った実時刻を使う。推測しない）
- **`transparency: transparent` / `availability: FREE` の終日予定は「空き扱い」と明記**して表の外に出す（丸1日埋まって見えるのを防ぐ）
- **2時間以上のまとまった空きは末尾に集計して出す**。これがご主人様が今日の計画を立てるときの根拠になる
- 参加者名・場所・Meet の有無は分かる範囲で1行に添える。**会議URLそのものは日報に書かない**
- カレンダーが取れなかったら「カレンダー取得失敗」と正直に書き、表は出さない（空の表を捏造しない）

⚠️ **当日イベントがある日は、ここで必ず現在時刻と突き合わせる**。2026-07-29 に、終日イベント（10:00開始）が既に進行中なのに気づかず「準備」を候補に挙げる失敗をした。ブリーフィングを出す前に、**いま進行中の予定が無いか**を確認すること。

## フェイルセーフまとめ

| 壊れる条件 | 挙動 |
|---|---|
| 昨日の日報が無い | 「日報なし」と報告して続行 |
| run.sh が終了コード3（launchd の集計が10分以上継続） | 既存 data.js を読み「集計中のため暫定値」と明記 |
| run.sh がその他の失敗 | 既存 data.js を読み「（前回更新: 日時）」と付記 / data.js も無ければ「使用量取得失敗」 |
| serve.sh が終了コード2（ポート衝突） | `file://.../index.html` をリンクとして出し、衝突している旨を添える |
| serve.sh が終了コード1（起動失敗） | 同じく file:// フォールバック。`serve.log` の確認を促す |
| ctx が壊れている | daily-ai-log 側のチェックに従いスキップ報告 |
| Todo.md が無い・空 | 「Todo.md なし」と報告して続行 |
| sync-settings.sh が無い・エラー | 黙ってスキップ（ドリフト検知は補助機能なので朝を止めない） |
| カレンダーが取れない（MCP未接続・認証切れ） | 「カレンダー取得失敗」と報告し**表は出さない**。空の表を捏造しない |
| 今日の予定が0件 | 「今日は予定なし」と1行だけ書き、空きは 09:00–18:00 として扱う |
| 今日の日報が無い | 日報テンプレで新規作成してから追記（2026-07-28変更） |
| `## 朝のブリーフィング` が既にある | 追記しない（同日2回実行の二重貼り防止） |

どのステップが欠けてもブリーフィング自体は必ず出す。**全滅したときだけ**「今朝は材料が集められなかった」と正直に言う。
