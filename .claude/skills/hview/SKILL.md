# hview

`hview <file>` は、HTML か Markdown のファイルを、実行したペインの右に html-viewer のペインとして開く。ユーザーは端末を離れずにページを読める。

## 一番大事な制約：ページは画像として映る

html-viewer は、裏で Chrome に描かせた結果を画像にしてペインへ映す。ユーザーはページの中を**クリックできない。ホバーも文字の選択もできない**。できるのは上下のスクロールだけ（ホイール、またはペインをクリックするか `Cmd+L` で入ってから `j` / `k`）。

だから、操作しないと読めない部品を使わない。

| 使わない | 代わりにこう書く |
|---|---|
| 折りたたみ（`<details>`、アコーディオン、「もっと見る」） | 最初から全部開いた状態で書く。長いなら見出しで区切る |
| タブ切り替え、トグル、ボタンで出し分ける表示 | 全部を縦に並べる |
| ホバーで出る説明（ツールチップ、`title` 属性） | 本文か注記にそのまま書く |
| リンク（ページ内の目次リンクも外部リンクも） | URL やパスを文字として見える形で書く |
| 入力欄、スライダー、並べ替えやフィルタ | 結果を決めた形で書く。切り口が複数要るなら表を分ける |
| 横スクロール（幅の広い表やコード） | ペインの幅に収める。列を減らすか、表を分ける |
| アニメーション、時間で変わる表示 | 最終の状態を静止で書く |

`window.claude.*` など、claude.ai の Artifact でしか動かない機能も動かない。

## 書き方

- 置き場所は、作業中のプロジェクトの `.claude/tmp/`（無ければ作る）。ファイル名は中身が分かる英小文字とハイフン（例 `auth-flow.html`）
- 1 ファイルで完結させる。CSS は `<style>` に書く。外部の画像やフォントの読み込みに頼らない
- ペインは画面の半分ほどの幅で開く。本文は 1 段組みにし、固定の広い幅を指定しない
- 背景は白で映る。文字は濃い色にする
- 図は mermaid が使える。`<pre class="mermaid">` の中に書く。自前の `<script>` で mermaid を読み込んでも描かれない。図の中の改行は `<br/>` ではなく `&lt;br/&gt;` と書く
- Markdown（`.md`）もそのまま開ける。文章と表が中心なら Markdown のほうが速い
- ページは 60,000px で切られる。長くなるなら分ける

## 開き方

```sh
hview <ファイルのパス>
```

- 開けるのは `.html` / `.htm` / `.md` / `.markdown` / `.mdown` だけ
- 実行したペインの右に開く。ユーザーが別のタブを見ていても、そちらには出ない。キーボードも奪わない
- ファイルを書き直すと、数秒で自動で描き直される。同じファイルを直すときは、`hview` をもう一度実行しない（ペインが増える）
- Herdr の窓が開いているときだけ動く。`herdr-app が見つからない` と出たら、ファイルのパスを伝えて止める
- ペインが「読み込み」のまま止まったら `touch ~/.config/herdr-app/mods/html-viewer/place.js`
- 描画のエラーはペインの中に赤字で出る。`herdr-app status` の `errors` には出ないので、それだけ見て「エラーなし」と言わない

## 開いたあと

- 何を開いたか、ファイルのパスと一緒に 1〜2 行で伝える。ページの中身を端末に繰り返さない
- ペインは閉じない。閉じるのはユーザーが頼んだときだけ
