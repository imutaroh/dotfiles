# 多視点FBループ（仕上げモード）

公開級に磨くための多エージェント反復レビュー。2026-08-12 の herdr 記事ブラッシュアップ（4ラウンドで3視点全PASS）で確立した型。

## 発動条件（オプトイン・常時実行しない）

- 公開前の最終仕上げ、または**既公開記事の改訂**のとき
- ご主人様が「ブラッシュアップして」「FB部隊で」等と明示したとき
- コスト目安: エージェント4体×3〜4ラウンド。初稿の下書きに回すのは過剰

## 部隊編成（model は必ず明示。Fable 禁止）

| 名前 | model | 役割 |
|---|---|---|
| brushup | opus | **唯一の編集者**。型の適用・FB反映。ラウンドをまたいで文脈保持 |
| fb-editor | opus | プロ編集者レンズ: 構成・見出しリズム・冗長・図と本文の噛み合い |
| fb-reader | sonnet | 想定読者レンズ（対象ツールを知らない読者を明記）: 詰まり・離脱・次の一歩 |
| fb-senior | opus | シニアエンジニアレンズ: 技術的正確さ・言い切りの危うさ・信頼性。**実機/公式での裏取りを許可**（WebFetch・CLI実行） |

ファイルを編集するのは brushup だけ。レビュアーは read-only。図の生成・検品は main が担当（figure-style.md 参照）。

## 開始前に固定すること（brushup とレビュアー全員のプロンプトに入れる）

1. **声の保護リスト**: 記事から著者の声（口癖・物語・自己開示・締めの一言）を具体的に列挙し、「消す・薄める提案は禁止」と明記する。これがないと FB ループは記事を無難な文章に磨耗させる
2. **捏造禁止**: 体験談・数字の新規追加は提案も禁止
3. **git 操作禁止**: published: true の記事は特に、push は必ずご主人様の指で（Studio 規約）

## ループ手順

```
R1: brushup が型を適用（短段落・見出し・数字前出し・図スロット設計）
    → main が図を生成・検品・挿入（figure-style.md）
    → 3レビュアー並列でFB
R2〜: main が必須指摘を統合して brushup へ差し戻し → 反映 → 3レビュアー再FB
    （ブラッシュアップするたびに必ずFBを回す）
全員PASS後: 任意指摘から採用分だけ最終ポリッシュ → 回帰チェック限定の確認ラウンド → 完了
```

### main（リード）の裁き方

- **必須指摘が複数レビュアーで衝突したら、main が統合文言を決めて指定する**（brushup に判断を丸投げしない）
- **任意指摘の採否は main が決める**。採用基準: 正確性に関わる／安くて確実に品質が上がる。不採用は理由付きで brushup に伝える（「触るな」リスト）
- **声・タイトルに関わる指摘は反映せず、ご主人様への最終報告に回す**

## 収束ガード（これを外すと無限ループする）

1. **判定様式を固定**: レビュアーは1行目に `判定: PASS / FAIL`。**必須指摘0件なら必ずPASS**。必須＝「直さないと読者体験・正確性が実際に損なわれる」もの。好み・微調整は任意に分離し、判定に影響させない
2. **すべての指摘に引用を義務付ける**（該当箇所20〜60字＋問題＋具体的修正案）。抽象的助言（「もっと具体的に」）は禁止
3. **最終ラウンドは回帰チェック限定**: 「この○件の編集による回帰がないかだけ確認。新規の指摘拡張はしない。PASS/FAIL＋FAIL時のみ理由を1〜5行」と明示する
4. レビュアーには毎ラウンド「基準は前回と同じ厳しさを維持し、PASSを安売りしない」と添える（甘くなる方向のドリフトも防ぐ）

## レビュアープロンプト雛形（共通部）

```
あなたは【レンズ名】としてZenn記事をレビューします。対象: <ファイルパス>
（画像も必要なら Read で確認可）

## 前提（指摘対象外の仕様）
- 著者の声はこの記事の価値: 【保護リストを列挙】。消す・薄める提案は禁止
- 体験談・数字の追加提案も禁止

## 見る観点
【レンズ別の観点。editor=構成/リズム/図の噛み合い、reader=詰まり/次の一歩（ペルソナ明記）、senior=正確さ/言い切り/信頼（実機・公式と照合してよい）】

## 出力形式
1行目: `判定: PASS` または `判定: FAIL`
- 必須指摘（0件なら判定PASS）: 「該当箇所の引用（20〜60字）/ 問題 / 具体的な修正案」
- 任意指摘（判定に影響しない）: 同形式で簡潔に
抽象的な助言は書かない。SendMessage で main 宛てに報告。
```

## 完了報告に含めるもの

- ラウンド表（各視点の PASS/FAIL 推移）と主な改善点
- 声が無傷であることの確認
- **未反映の指摘**（タイトル等の本人判断事項）の提示
- push はしていないことと、公開手順の案内
