# zenn-studio — Zenn 制作室

## 前提

- **出力先リポ**: `/Users/imutaakihiro/repos/imutaakihiro/ObsidianImus/Studio/zenn-claude-guide/`（Zenn連携済み・main 直 push 運用・2026-08-12 に Studio/ 配下へ移動）
  - 記事 = `articles/<slug>.md`、本 = `books/<slug>/`（config.yaml ＋ 章md ＋ cover.png）
  - 画像はリポ直下 `images/` に置き、本文からは `/images/xxx.png` で参照
- **公開の主導権はご主人様**: 下書きは常に `published: false`。`true` への変更・公開 push はご主人様の明示指示時のみ
- **git はパス指定**: `git add` は自分が作った/編集したファイルだけをパス指定。push 前に `git pull --rebase`
- **codex のカレントディレクトリに注意**: シェルの cwd はコマンド間でリセットされることがある。codex 実行は毎回 `cd <リポ> && codex exec ...` の形にする
- 大きいファイルは骨子 `Write` → 節ごと `Edit`（ツール呼び出しパース失敗の予防）

## Step 1: 対象とタイプを確定する

- 何を作る/直すのか: 記事（`tech` / `idea`）か、本の章か、図解だけか
- 素材: 会話履歴（最多・実際に起きたことだけ書く）/ 既存ドラフト / 口頭のネタ。薄ければ「実体験・ハマり・数字」を1〜2問だけ補う
- slug は `a-z0-9` とハイフン・アンダースコアで **12〜50文字**

## Step 2: 執筆する

### 冒頭は「読者の内心フック」で始める（この型が既定）

```
（読者の状況を受ける1行。例: ここまで読んだあなたは、たぶんこう思っています。）

「（内心のセリフ1: 読者が言いそうな疑問・反論）」

「（内心のセリフ2: 別角度の本音）」

（橋渡し1行 → そのまま本文へ接続）
```

- 抽象的な前置き（「〜について書きます」）で始めない
- 本の章では、前章の章末が撒いた問いをセリフで回収する（章＝別ページの Zenn ではリレーが切れるため、章単独で読めるようにする）

### 本文の型

- 短段落（1段落2〜3文）。見出しを細かく割る
- 数字で具体化（「簡単」ではなく「コード0行」「30分→30秒」）。ハマりはエラー実物・原因・回避策をセットで正直に
- 両論併記が要るテーマは、相手側を最新情報で最大限強く評価してから差分を述べる（ストローマン禁止）
- まとめは箇条書き4点以内＋最後に一言の主張
- 本の章は冒頭に `:::message` の装備ボックス、章末は「次章への問い」で締める
- 捏造禁止: 実体験にない手順・数字を書かない。一次ソースで未確認の数字は本文に入れない。APIキー等は `xxxx` にマスク

### frontmatter（記事）

```yaml
---
title: "タイトル（70字以内。数字か具体ワードを入れる）"
emoji: "📝"        # 1文字
type: "tech"       # tech / idea
topics: ["claudecode", "ai"]  # 最大5つ・小文字英数字
published: false
---
```

## Step 3: 図解を入れる

**必ず [references/figure-style.md](references/figure-style.md) を読んでから始める**（スタイル定義・共通プロンプトブロック・codex コマンド・検品基準が全部そこにある）。

手順の骨格（順番を守る）:

1. **配置設計**: 図が効くスロットを洗い出す（1枚1概念。表で足りる箇所・文章で立っている箇所には入れない）
2. **見本1枚 → ご主人様の承認 → 量産**: いきなり量産しない。スタイルの見本を1枚生成して承認を取ってから残りを並列生成する（このセッション運用で106枚がトーンぶれゼロだった実証済みの型）
3. **生成**: codex exec をバックグラウンド並列（同時5本程度まで）
4. **全数検品**: 生成画像を必ず Read で開いて確認。基準は figure-style.md
5. **挿入**: alt テキストに図の要旨を書いて `![要旨](/images/xxx.png)`

## Step 4: 章扉カード（本のみ・指示があれば）

各章の frontmatter 直後（`:::message` の上）に、タイポグラフィ主体の章扉カードを置く。テンプレは figure-style.md の「章扉」節。キーワードは各章の装備ボックスから3〜5語に凝縮する。

## 仕上げモード: 多視点FBループ（オプトイン）

公開前の最終仕上げ・既公開記事の改訂・「ブラッシュアップして」の明示指示があったときだけ、**[references/review-loop.md](references/review-loop.md) を読んで**多エージェントFBループを回す（brushup＋編集者/読者/シニアの3レビュアー、全員PASSまで反復）。エージェント4体×数ラウンドとコストが重いので、初稿の下書きには使わない。

## Step 5: 公開前点検 → push

**必ず [references/publish-checklist.md](references/publish-checklist.md) のチェックを全部実行してから** パス指定 add → commit → `git pull --rebase` → push する。点検で1つでも落ちたら push しない。

push 後は「数分で https://zenn.dev/dashboard/deploys に反映される」ことと、デプロイ結果（失敗・スキップの有無）の確認を案内する。

## Step 6: 完了報告

- ファイルパス・slug・構成（見出しリスト）
- 公開手順の案内（`published: true` はご主人様の指示待ち）
- **自信のない数字・手順・固有名詞を正直に列挙**して事実確認を仰ぐ（特に「僕」の体験として書いた箇所）
